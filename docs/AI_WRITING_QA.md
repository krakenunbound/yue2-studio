# AI writing reliability QA — 2026-09-15

## Scope

YuE2 writing calls used by Custom Create, Easy Create, Live, library lyric editing, English display translation, blank-title naming, and both sound-effect prompt helpers. Live tests used a saved Ollama configuration on a private-network test server. Provider credentials and the saved ban list were not changed.

## Fixes

- Serialize complete writing operations, including retries; reject overlapping requests with HTTP 409. Bound input, output, context, generation length, and request duration.
- Stop closes the streaming request without unloading the model. Keep-alive remains unlimited. Ignore stale UI results after cancellation, stop Live draw timers, and guard polling. Add a Stop control to Effects prompt enhancement.
- Validate generated titles and sung lines against the saved ban list; retry invalid candidates, then report a clear error rather than returning banned or damaged text. Normalize invisible/fullwidth characters and handle unspaced CJK/Thai bans. Preserve lyric line breaks while cleaning brief text.
- Reject duplicate and near-duplicate titles against the library and titles issued or optimized during the running app session, including common edition suffixes such as (Live). Ask for a new title; never silently append numbers or timestamps. Submitting a title just generated by the app does not unnecessarily rename it.
- Repair title-only parsing, a section tag on the title line, unwanted JSON/markdown wrappers, duet role labels, parallel romanization, and dangling title punctuation.
- Give Optimize the actual source lyrics. Preserve section order, story vocabulary, chorus hooks, and sung quantities. Reject rewrites that drift; remove only extra trailing sections following a matching source structure.
- Translate the actual source into English, retaining line count and tags while leaving sung lyrics unchanged.
- Give failed drafts back to the writer for bounded repairs at a lower temperature, within the context limit.
- Enforce compact style/effect output and instrumental constraints. Respect Easy chat's ready=false response so a greeting cannot start a song.

Across the recorded rounds there are over **230 real app-route calls**, plus direct provider traces and UI/control tests. ## Reproduce

Start the app backend on localhost port 7794, then run:

```powershell
python -m pytest python/tests -q
npm run build
python scripts/check_ai_assist.py --round verification
python scripts/check_ai_controls.py
```

The live script requires SSH access to the configured Linux test host. It sends requests sequentially, checks GPU health between them, and stops on a detected GPU fault. The controls script deliberately sends one overlapping request and cancels one active request. Neither script requests music or effect audio generation.

## Practical limits

Finite tests cannot guarantee a failing GPU will never crash again or that every creative output has perfect meaning. The persistent 110 W GPU power cap mitigates the observed device-level failure; it is not a driver repair. Text validation deliberately reports an error if bounded retries cannot satisfy the contract. Title history covers saved library songs and the current application session; discarded, unsaved titles are not remembered across app restarts. Translation preserves meaning rather than applying lyric bans that would alter the original. Ban matching includes configured terms/patterns and known aliases, not every possible translation or semantic paraphrase.
